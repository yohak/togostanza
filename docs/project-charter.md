# プロジェクト憲章

この文書では、TogoStanza Remakeの計画、調査、仕様判断で共有する基本方針を定める。リメイク版で何を守り、何を見直し、判断の根拠をどこに記録するかを確認するための出発点として扱う。

用語の定義は、[用語集](./UBIQUITOUS_LANGUAGE.md)を基準とする。

## 目的

このリポジトリでは、現行版の既存挙動と実プロジェクトでの使われ方を調査し、リメイク版として維持、再設計、破棄する対象を判断する。

リメイク版は、現行版の完全なクローンを目指さない。既存の利用実態を重視しながら、古い機能、複雑な機能、利用根拠が弱い機能を整理できる実装を目指す。

## 互換性方針

互換性は、**Stanza提供者**、**Stanza開発者**、**Stanza利用者**の立ち位置に優先順位を付けて判断しない。対象が**利用契約**か**開発契約**かによって、守るべき範囲を切り分ける。

**利用契約**では、既存ページのHTML埋め込みに関わる契約を壊さないことを重視する。custom element名、属性、データ連携、Webサイト上での表示や操作に影響する変更は慎重に扱う。

**開発契約**では、既存Stanzaソースを中心に維持する。HTML、JS、CSS、設定などの既存ソースはなるべく活かすが、小規模な手修正は許容する。

一方で、CLI、build環境、依存関係、コマンド体系は、既存Stanzaソースと利用契約を守るために再設計できる。再設計する場合は、理由と移行手順を記録する。

## 実プロジェクトの扱い

**実プロジェクト群**は、互換性判断の強い根拠として扱う。ただし、絶対に変更できない互換対象とはしない。

**metastanza**は、可能な限り固定点として扱う。現行の使い方から外れる判断を行う場合は、理由と影響範囲を記録する。

**TogoMedium Stanza**は、互換性の固定点というより、検証と発見のための実プロジェクトとして扱う。作者側で調整できる前提があるため、必要なソース修正や移行手順も判断材料に含める。

## 記録先

観測された現行版の挙動は、`docs/investigation/` に記録する。ここでは、互換性判断の前提になる事実を扱う。

リメイク版で維持、再設計、破棄する判断は、`docs/spec/` に記録する。再設計に伴う理由、影響範囲、移行手順も、同じく `docs/spec/` の移行メモとして残す。
